# 공통 문서 템플릿

각 문서는 아래 골격을 따르되, 프로젝트에 없는 항목은 억지로 채우지 않는다. 모든 사실은 실제 코드/설정 파일에서 확인한 것만 쓰고, 필요하면 근거 파일 경로를 함께 적는다.

---

## introduction.md

```markdown
# 소개

## 한 줄 설명
<프로젝트가 무엇을 하는지 한 문장. CLAUDE.md/PRD가 있으면 참고하되 코드로 확인.>

## 목적과 핵심 가치
<왜 존재하는가, 어떤 문제를 푸는가. 특징적 제약이 있으면 명시 (예: E2E 암호화).>

## 기술 스택
<언어·프레임워크·DB·주요 라이브러리. package.json / 설정으로 확인한 실제 버전대.>

## 저장소 구성
<모노레포면 워크스페이스 목록과 각 앱/패키지 역할. 디렉터리 트리 최상위 수준.>

## 로컬 실행
<개발 서버 기동 방법. Makefile/scripts/README 근거.>
```

## conventions.md

```markdown
# 컨벤션

## 코드 스타일
<네이밍(camelCase/PascalCase/UPPER_SNAKE 등), 파일 구성 원칙, 불변성/에러 처리 규칙. .claude/rules·ESLint·Prettier 근거.>

## 커밋 메시지
<형식(예: `<type>: <설명>`), 허용 type 목록, 좋은/나쁜 예.>

## 브랜치 전략
<기반 브랜치, 브랜치 네이밍(feat/fix/...), 병합 흐름, 보호 규칙(pre-push 훅 등).>

## 금지 사항
<수정/삭제 금지 대상(빌드 산출물, lock 파일, 시크릿, 적용된 마이그레이션, 암호 계약 상수 등)이 정의돼 있으면 명시.>
```

> 커밋/브랜치/컨벤션은 `CLAUDE.md`, `.claude/rules/`, 설정 파일에 명문화돼 있는 경우가 많다. 그 문서들을 근거로 삼되, 실제 커밋 히스토리(`git log`)로 관행과 일치하는지 가볍게 대조하면 좋다.
