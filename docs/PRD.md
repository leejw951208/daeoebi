# PRD. 대외비 (비밀번호 보관함 + 가계부)

> 사이트별 비밀번호와 월별 가계부를 **종단간 암호화(E2E)**로 보관·관리하는 1인용 웹 서비스. Cloudflare로 공개 호스팅하되 Cloudflare Access로 앞단을 차단하고, passkey(WebAuthn)로 인증한다. 서버는 본문 평문을 절대 복호화하지 않고 암호문 블롭만 저장·패스스루한다.

---

## 1. 요약

대외비는 두 가지를 한 명의 사용자가 안전하게 관리하는 웹 앱이다. (1) 은행·페이·쇼핑 같은 **사이트별 비밀번호**를 사이트 → 비밀번호 구조로 보관하고, (2) **월별 수입·지출(가계부)** 을 기록·분류하고 저축·투자까지 함께 본다. 두 영역 모두 본문(비밀번호 필드·가계부 금액)은 WebAuthn PRF로 도출한 vault 키로 AES-256-GCM 암호화해 저장하며, 키는 서버에 두지 않는다. 인증은 passkey(생체·기기), 공개 노출은 Cloudflare Access가 1차로 막고, 기기 분실에 대비해 1회 발급 복구코드로 키를 추가 래핑한다.

## 3. 배경

은행·카드·증권·페이·쇼핑몰의 비밀번호와 그에 딸린 번호(계좌번호, 결제비밀번호 등)가 머릿속과 메모 앱에 흩어져 있고, 매달 돈이 어디로 나가는지도 흩어진 기록으로만 남는다. 범용 비밀번호 관리자는 무겁고, 가계부 앱은 데이터를 매니지드 클라우드에 맡겨야 하며, 메모 앱은 평문이라 위험하다. 필요한 건 비밀번호와 가계부를 한 곳에서 단순하게 다루면서도 본문은 확실히 암호화되고 내가 통제하는 서버에 두는 가벼운 개인 도구다.

대외비는 비밀번호 보관함으로 시작해 같은 E2E·인증 기반 위에 가계부(수입·지출·고정 지출·저축/투자)를 얹었다. 두 도메인은 같은 잠금해제 세션·같은 vault 키를 공유하되 데이터는 분리돼 있다.

**왜 지금인가.** 이미 갖춰진 NestJS·Prisma·Next.js·암호화(AES-256-GCM)·모바일 UI 자산을 두 도메인에 그대로 재사용할 수 있고, Cloudflare로 도메인을 등록해 어디서나 접속하려는 요구가 있기 때문이다.

---

## 4. 목표

**목표.** 한 명의 사용자가 비밀번호와 가계부를 어디서나 안전하게 보관·열람하되, 공개 인터넷에 노출되더라도 passkey·Cloudflare Access·암호화의 다층 방어로 본문이 보호받게 한다.

**왜 중요한가.** 흩어진 비밀번호와 지출 기록을 한곳에 암호화해 두면 분실·유출 위험이 줄고, 구조화된 목록·대시보드 덕분에 빠르게 찾고 파악할 수 있다.

**비전·전략 정합성.** 무겁지 않은 1인용 도구로, 본인이 통제하는 단일 서버에서 운영하는 프라이버시 우선 방향에 부합한다.

### 핵심 성과 지표 (Key Results)

| KR | 측정 방식 | 목표 |
|----|----------|------|
| 평문 미저장 | DB에 저장되는 비밀번호·가계부 본문(금액·필드) 중 암호화되지 않은 건수 | 0건 |
| 무단 접근 차단 | Cloudflare Access를 통과하지 못한 외부 요청이 앱에 도달하는 비율 | 0% |
| 무차별 대입 방어 | passkey 인증(인증기 차원 방어) + 복구코드 5회 실패 후 추가 시도 차단 동작 | 100% backoff 발동 |
| 열람 속도 | 잠금해제 상태에서 비밀번호 1건 복호화·표시 시간 | 200ms 이내 |
| 데이터 통제 | 비밀번호·가계부 본문에 접근 가능한 외부 제3자(매니지드 서비스) 수 | 0 (단일 자가 서버) |

## 5. 시장 세그먼트

**누구를 위해 만드는가.** 다음 일(job)을 가진 단일 사용자다.

- 사이트별 비밀번호와 결제비밀번호·계좌번호를 한곳에 정리해 두고 싶다.
- 매달 수입·지출과 저축·투자를 한 화면에서 파악하고 싶다.
- 그 본문이 평문으로 떠돌지 않고 확실히 암호화되길 원한다.
- 집·회사·외부 어디서든 내 도메인으로 접속하고 싶지만, 공개 노출 위험은 최소화하고 싶다.
- 매니지드 클라우드에 데이터를 맡기지 않고 내가 운영하는 서버 한 대에 두고 싶다.

**제약.**

- 단일 사용자, 한국어 환경.
- 공개 도메인으로 접근하되 Cloudflare Access가 앞단을 차단한다.
- 비밀번호·가계부 본문은 반드시 암호화한다.

## 7. 솔루션

### 7.1 사용자 흐름

```
[인터넷] → Cloudflare Access(이메일 OTP 등 1차 차단)
         → passkey 인증(생체·기기) + WebAuthn PRF로 vault 키 도출
         → 세션(SameSite=Strict 쿠키, 도출 키는 서버 메모리에만)
         → 비밀번호 탭: 사이트·비밀번호 조회·열람·추가·수정, 백업 export/import
         → 가계부 탭: 월 예산·지출·고정 지출·저축/투자 대시보드
         → idle N분 후 키 폐기(재잠금) → passkey 재인증
```

- 인증 없이 접근 가능한 **데모 모드(`/demo`)** 가 별도로 있다. 저장 없이 가계부 UI를 체험만 한다.

### 7.2 핵심 기능

**F1. passkey 등록·인증·복구코드**

- 첫 실행 시 passkey를 등록한다(생체·기기 인증). 서버는 WebAuthn 공개키·credentialId·signCount만 저장하고, PRF 출력이나 도출 키는 저장하지 않는다.
- 등록 직후 고엔트로피 복구코드를 1회 발급한다. 복구코드로 vault 키(DEK)를 추가 래핑하며, "저장했습니다" 확인 전에는 등록을 완료하지 않는다.
- 재방문 시 passkey 인증 한 번으로 잠금해제한다. 기기 분실 시 복구코드로 접근을 복구하고 새 passkey를 재등록한다. 복구코드 입력은 5회 연속 실패 시 60초 backoff를 발동한다.

**F2. 잠금해제/재잠금**

- passkey 인증 시 WebAuthn PRF 출력으로 vault 키(DEK)를 언랩해 서버 메모리에 둔다. 이 키로 비밀번호·가계부 본문을 열람·추가·수정한다.
- idle N분 경과 시 키를 폐기해 자동 잠근다. 잠금 상태에서 본문 접근은 거부하고 passkey 재인증을 요구한다.
- 키 정확성은 래핑 DEK의 AEAD authTag 검증으로 확인한다(언랩 실패 시 거부).

**F3. 사이트 CRUD (비밀번호)**

- 사이트를 라벨(예. 우리은행, 네이버페이)과 선택적 아이콘으로 등록·수정·삭제한다.
- 사이트 라벨은 검색용 평문이다. 사이트 삭제 시 하위 비밀번호도 함께 삭제한다(cascade).

**F4. 비밀번호 CRUD (사용자 정의 필드)**

- 항목을 제목 + 사용자 정의 필드(이름·값) 여러 개 + 메모로 등록한다. 폼은 (1) 제목 → (2) 필드 추가 → (3) 값 입력 → (4) 확인 순서로 진행하며 필드는 추가·삭제·이름 변경·재정렬이 가능하다.
- 필드 집합과 메모는 하나의 JSON payload로 직렬화해 AES-256-GCM으로 암호화하고 ciphertext·iv·authTag로 저장한다. 필드 이름도 암호화되며 평문으로 남는 것은 제목(label)뿐이다.
- 열람 시 잠금해제 상태에서 복호화한다. 각 필드 값은 기본 마스킹하고, 표시·복사 후 자동 재마스킹한다. 항목은 사이트에 속한다(siteId).

**F5. 검색 (비밀번호)**

- 사이트·비밀번호 라벨(평문)에 대해 대소문자 무시 부분 일치 검색한다. 본문은 검색 대상이 아니다.

**F6. 백업 export / import (비밀번호)**

- 전체 Site·Secret을 **암호문 그대로** export하고, import 시 id 충돌을 reject·skip·replace 모드로 처리한다. 백업 대상은 비밀번호 도메인뿐이며 가계부 데이터는 포함하지 않는다.

**F7. 가계부 — 수입·예산·지출**

- 월 단위로 수입(Income)을 기록하고, 이를 그 달 예산으로 삼는다. 지출(Expense)은 날짜·금액·항목·카테고리로 등록·수정·삭제한다.
- 대시보드에서 남은 예산·지출 비율·카테고리별 분해·달력·선택일 상세를 본다. 지출이 예산을 넘으면 앰버 경고 배너를 표시한다.

**F8. 가계부 — 고정 지출**

- 매월 자동 생성되는 고정 지출 템플릿(RecurringExpense)을 둔다. 시작월·생성일·기간(개월, 무기한 가능)·지출 방식(method)을 가지며, 클라이언트가 매월 지출 인스턴스를 멱등 생성한다((recurringId, period) 유일). 해제 시 자동 생성만 멈추고 기록은 유지한다.

**F9. 가계부 — 자산 카테고리**

- 지출·고정 지출을 분류하는 카테고리(AssetCategory)를 둔다. 고정 카테고리(코드 보유, 저축·투자 앵커 포함)는 시드되고 수정·삭제 불가이며, 사용자 카테고리는 이름·색(#rrggbb)으로 추가한다. 이름은 중복 불가.

**F10. 가계부 — 저축·투자·쌈짓돈**

- 적금 계좌(SavingsAccount: 잔액·목표), 투자 포지션(InvestmentPosition: 원금·수익률), 저축 박스/쌈짓돈(SavingsBoxTxn: 입출금)을 관리한다. 저축·투자 대시보드는 고정 카테고리 code(SAVINGS/INVESTMENT)로 분류된 지출을 "기여"로 집계한다.

> 금액·목표·잔액 등 본문은 모두 암호문이며, 총액·진행률·손익 계산은 클라이언트가 복호화 후 수행한다(서버는 집계하지 않는다).

### 7.3 데이터 모델

평문으로 남는 것은 검색·조회·스케줄에 필요한 메타(라벨, month/date, 카테고리 name·color, method, returnRate 등)뿐이고, 금액·필드 본문은 모두 암호문 블롭(`iv`·`ciphertext`·`authTag`)이다.

**인증·비밀번호**

| 모델 | 핵심 필드 | 비고 |
|------|----------|------|
| `Passkey` | id, credentialId, publicKey, signCount, transports?, createdAt | WebAuthn 자격증명. 공개키만 저장 |
| `RecoveryCode` | id="singleton", codeHash, used, failCount, lockUntil | 복구코드. 분실 복구·backoff |
| `VaultKey` | id="singleton", prfWrappedDek, prfSalt, recoveryWrappedDek, keyVersion | DEK를 PRF·복구코드로 각각 래핑. DEK 원본 미저장 |
| `Site` | id, label, icon?, createdAt | 이름 중심. 라벨은 평문 |
| `Secret` | id, siteId(FK), label, iv, ciphertext, authTag, kdfVersion, createdAt, updatedAt | label만 평문. 필드·메모는 payload로 암호화. siteId cascade |

**가계부**

| 모델 | 핵심 필드 | 비고 |
|------|----------|------|
| `Income` | id, month("YYYY-MM", 평문), 암호문 블롭 | 월 수입(월별 다건). 그 달 예산 산정에 사용 |
| `Expense` | id, date(평문), categoryId?, recurringId?, period?, removed, 암호문 블롭 | 일반 지출 또는 고정 인스턴스 |
| `RecurringExpense` | id, dayOfMonth, startMonth, termMonths?, method?, active, categoryId?, 암호문 블롭 | 고정 지출 템플릿. 인스턴스 cascade |
| `AssetCategory` | id, name, color, code? | 고정(code 보유, 수정·삭제 불가)+사용자 생성(code null) |

**저축·투자**

| 모델 | 핵심 필드 | 비고 |
|------|----------|------|
| `SavingsAccount` | id, name, color(평문), 암호문 블롭({base, goal}) | 적금 계좌(다건) |
| `InvestmentPosition` | id, returnRate(평문 문자열), 암호문 블롭({base}) | 투자 포지션(사실상 싱글톤) |
| `SavingsBoxTxn` | id, type(in/out), source(cash/savings), date(평문), 암호문 블롭({amount, memo}) | 쌈짓돈 입출금(생성·삭제만) |

예시 매핑.
- 우리은행(Site) → 결제비밀번호(Secret)
- 2026-07 수입(Income) → 그 달 예산
- 통신비(RecurringExpense, 매월 25일) → 매월 지출 인스턴스(Expense) 자동 생성

### 7.4 기술

- **모노레포.** pnpm workspace(`apps/web`, `apps/api`).
- **프런트엔드.** Next.js 15 App Router + React 19. 모바일 우선 레이아웃·PWA·접근성. 비밀번호 탭과 가계부 탭.
- **백엔드.** NestJS 10 + Prisma. auth·vault(비밀번호)·asset(가계부·저축/투자) 도메인 모듈 + common 인프라. passkey/WebAuthn 인증, PRF·복구코드 키 래핑, 암호문 패스스루 REST 엔드포인트.
- **저장소.** **PostgreSQL**(Prisma `postgresql`, `pg_trgm` 확장으로 라벨 검색). 백업은 `pg_dump`.
- **암호화.** 본문은 랜덤 데이터 키(DEK)로 AES-256-GCM(nonce 12바이트, tag 16바이트) 암호화한다. DEK는 WebAuthn PRF 출력에서 도출한 키와 복구코드에서 도출한 키로 각각 래핑한다. 키 버전닝으로 회전 경로를 확보한다.
- **앞단·인증.** Cloudflare(도메인 + DNS + Access + Tunnel). 앱·DB는 직접 운영하는 단일 서버에 함께 둔다. CORS·Origin은 내 도메인만 허용.

### 7.5 배포

- **단일 서버 한 대**(Vultr 등)에 web·api·postgres를 docker compose로 함께 세팅한다.
- `cloudflared` Tunnel이 바깥으로 연결을 열어 포트 개방·고정 IP 없이 외부 접속을 가능하게 한다(공개 인바운드 0). Tunnel은 앱과 분리된 별도 compose로 돌려 재배포가 SSH·터널을 끊지 않게 한다.
- Cloudflare Access를 도메인에 적용해 앱 도달 전에 신원을 차단한다. **Access 설정 누락은 배포 차단 사유**다.
- CI(GitHub Actions)가 이미지를 GHCR에 빌드·푸시하고 서버는 pull만 한다(1코어 VPS 빌드 부하 0). DB 백업은 R2로 cron. 매니지드 서비스(매니지드 Postgres·PaaS)는 쓰지 않는다.
- 상세 절차는 `docs/DEPLOY.md` 참조.

### 7.6 가정

- 사용자는 1명, 비밀번호·가계부 항목은 수백~수천 건 규모다.
- 단일 서버는 상시 가동되며 사용자가 OS·DB 백업을 책임진다.
- Cloudflare Access가 항상 활성화되어 있다(미설정 시 위협 모델 붕괴).
- passkey 기기와 복구코드를 모두 잃으면 본문 복구가 불가하므로, 등록 시 복구코드 저장을 강제하고 setup 직후 백업을 안내한다.

날짜 대신 상대적 단계로 표현한다. 현재 아래 범위가 모두 구현·동작한다.

| 단계 | 범위 | 상태 |
|------|------|------|
| 인증·보관함 | passkey 등록·인증, 복구코드·backoff, 잠금해제/재잠금, 사이트·비밀번호 CRUD, 검색, 백업 export/import | ✅ |
| 가계부 | 월 수입·예산, 지출 CRUD, 고정 지출(자동 생성·기간·방식), 자산 카테고리, 대시보드(예산 초과 경고 포함) | ✅ |
| 저축·투자 | 적금 계좌, 투자 포지션, 쌈짓돈(저축 박스) | ✅ |
| 데모 | 인증 없는 `/demo` 가계부 체험(미저장) | ✅ |
| 배포 | Cloudflare Tunnel + Access, GHCR CI/CD, R2 백업 | ✅ |

**후속 후보.** 추가 passkey 등록, 키 회전(re-key), 비밀번호 항목 정렬·태그, 가계부 데이터 export/import, 가져오기/내보내기 강화.

**넣지 않는 것.** 다중 사용자·회원가입, 브라우저 자동입력, 클라우드 동기화, 매니지드 인프라.

## 부록. 용어 정의

| 용어 | 설명 |
|------|------|
| 사이트 (Site) | 비밀번호를 묶는 최상위 단위. 라벨 + 선택적 아이콘. |
| 비밀번호 (Secret) | 제목(label) + 사용자 정의 필드·메모(암호화 payload) 1건. 사이트에 종속. |
| 필드 (Field) | 항목 안의 사용자 정의 이름·값 쌍. 값은 기본 마스킹. |
| payload | 한 항목의 필드 집합 + 메모를 직렬화한 JSON. 통째로 암호화되며 제목만 평문. |
| 수입 (Income) | 월별 수입 기록. 그 달 예산 산정에 쓰인다. month만 평문. |
| 지출 (Expense) | 지출 1건. 일반 지출 또는 고정 인스턴스(recurringId+period). date만 평문. |
| 고정 지출 (RecurringExpense) | 매월 자동 생성되는 지출 템플릿. 시작월·생성일·기간·방식(method)·활성 상태. |
| 자산 카테고리 (AssetCategory) | 지출 분류. 고정(code, 시드·읽기전용)+사용자(name·color). |
| 적금/투자/쌈짓돈 | SavingsAccount(적금 잔액·목표) / InvestmentPosition(원금·수익률) / SavingsBoxTxn(저축 박스 입출금). |
| passkey | WebAuthn 자격증명. 생체·기기로 인증하며 서버는 공개키만 저장. 피싱에 강하다. |
| WebAuthn PRF | passkey 인증 시 인증기가 내는 비밀 출력. vault 키 도출에 쓰며 서버에 저장하지 않음. |
| DEK (vault 키) | 비밀번호·가계부 본문을 암호화하는 랜덤 데이터 키. PRF·복구코드 도출 키로 각각 래핑해 보관. |
| 복구코드 | 1회 발급되는 고엔트로피 코드. DEK를 추가 래핑해 기기 분실 시 접근 복구에 사용. |
| AEAD | 인증 암호화(AES-256-GCM). iv·ciphertext·authTag 세 조각으로 저장. |
| Cloudflare Access / Tunnel | 앱 도달 전 신원을 차단하는 Zero Trust 앞단 / 포트 개방 없이 외부 접속을 여는 터널. |
| Unlock / Lock 상태 | vault 키(DEK)가 메모리에 있는 상태 / 폐기된 상태. |
